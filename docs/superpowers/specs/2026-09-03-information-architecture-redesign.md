## 1. 배경

Finance Web은 다음 세 가지 목표를 중심으로 만들어진 가족 가계부다.

1. 순저축률 30% 이상을 유지한다.
2. 매달 예산을 작성하고 지출 속도를 관리한다.
3. 어디서 많이 썼는지, 전월보다 무엇이 달라졌는지 빠르게 파악한다.

현재 앱에는 거래 관리, 파일 가져오기, 예산, 분석, 자산, 정기거래와 기준정보 관리까지 핵심 기능이 대부분 구현되어 있다. 다만 기능이 추가되는 과정에서 화면의 역할이 겹치고, 사용자의 업무 흐름보다 구현 단위를 기준으로 메뉴가 나뉘었다.

이번 개편의 목적은 기능을 줄이는 것이 아니라, 각 기능을 사용자가 예상하는 위치로 옮기고 한 화면이 하나의 질문에 집중하도록 정보 구조를 다시 정리하는 것이다.

## 2. 사용자의 핵심 업무

메뉴는 아래 업무의 빈도와 중요도를 기준으로 구성한다.

### 2.1 주간 업무: 거래 가져오기

```text
파일 업로드
  → 중복·추천 결과 확인
  → 필요한 항목 수정
  → 가계부 반영
  → 미분류 거래 정리
```

### 2.2 수시 업무: 거래 확인과 수정

```text
월 선택
  → 거래 검색·필터
  → 직접 입력 또는 기존 거래 수정
```

### 2.3 월간 업무: 예산 관리

```text
지난달 리뷰
  → 다음 달 예산 작성
  → 진행 중 지출 속도 확인
  → 필요하면 예산 또는 소비 계획 조정
```

### 2.4 월간·연간 업무: 분석

```text
전월 대비 변화 확인
  → 증가한 카테고리·가맹점 확인
  → 상세 거래로 이동
  → 다음 예산에 반영
```

### 2.5 월간 업무: 자산 확인·보정

```text
뱅크샐러드 업로드 시 잔액 스냅샷 자동 기록
  → 자동 스냅샷에 없는 계정(부동산·자녀 계좌 등)만 수동 보정
  → 순자산 및 자산 배분 확인
```

잔액 입력은 주 경로가 아니라 보정이다 (§7.6).

### 2.6 비정기 업무: 기준정보 설정

- 결제수단 추가·수정
- 카테고리 구조 변경
- 가맹점 분류 규칙 및 결제수단 별칭 관리
- 정기거래 규칙 관리
- 비밀번호 변경

## 3. 현재 정보 구조

### 3.1 현재 상위 메뉴

```text
직접 노출
├─ 가계부
├─ 대시보드
├─ 자산
└─ 인박스

분석·예산
├─ 분석
├─ 항목별 상세
├─ 예산
└─ 연간결산

설정
├─ 가져오기
├─ 결제수단
├─ 항목 관리
├─ 고정비용
└─ 계정 설정
```

모바일에서는 위 항목이 계층 없이 하나의 13개 링크 목록으로 합쳐진다.

### 3.2 현재 라우트와 역할

| 라우트 | 현재 역할 | 판단 |
|---|---|---|
| `/dashboard` | 연간·월간 KPI, 재무 건강, 예산, 분석표, 가맹점 | 범위가 지나치게 넓음 |
| `/ledger` | 거래 입력·수정·검색, 예산 경고, 인사이트, 지출 순위, 남은 돈·월말 예측·월 KPI | **사실상 월 대시보드**. 상단 절반이 이번 달 조종석이라 사용자가 대시보드 대신 이 화면을 먼저 연다. 조종석은 홈으로, 원장만 남긴다 |
| `/inbox` | 파일 업로드, 처리 통계, 거래 검토 | 업로드와 검토가 한 긴 화면에 혼재 |
| `/budgets` | 예산 현황, 편집, 목표 저축률, 감축 시뮬레이터 | 시뮬레이터까지 항상 펼쳐져 길고, "남은 돈" 정의가 홈과 다름. 현황+편집은 한 화면이 맞되 접힘이 필요 (§7.4) |
| `/budgets/review` | 월말 리뷰와 다음 달 예산 생성 | 예산의 하위 흐름으로 적절 |
| `/analysis` | 월·연간 분석, 이상 지출, 카테고리, 가맹점, 추이 | 월/연 토글로 **시간축 두 개를 한 화면에** 둠. 월간 부분은 거래와 같은 달의 다른 배율이라 거래 화면의 탭으로 합치고, 연간 부분은 연간 화면으로 보낸다 |
| `/category` | 선택한 카테고리의 상세 분석 | 분석에 카테고리 필터 하나 건 것과 같다. 거래·분석이 한 화면이 되면 **라우트 자체가 불필요** |
| `/report` | 연간 요약, 전년 대비, 현금흐름 예측 | 독립 연간 화면의 씨앗. 대시보드의 연 KPI·항목별 월별 표를 여기로 모아 연간 화면으로 키운다 |
| `/assets` | 자산 요약, 추이, 배분, 잔고 입력 | 조회와 편집 모드 분리 필요 |
| `/recurring` | 정기거래 규칙 편집과 월별 반영 | 설정과 실행이 혼재 |
| `/manage` | 결제수단, 카테고리, 가맹점 사전, 미분류 거래 | 설정과 작업 큐가 혼재 |
| `/settings` | 비밀번호 변경 | 계정·보안 설정으로 적절 |

## 4. 핵심 문제

### 4.1 같은 정보가 여러 화면에 반복된다

대시보드, 거래, 분석에 모두 수입·지출·순저축률·지출 상위 항목·인사이트가 표시된다. 사용자는 어느 화면이 정본인지 판단하기 어렵고, 애플리케이션은 유사한 데이터를 여러 방식으로 불러오게 된다.

반복의 원인은 **화면마다 시간축을 따로 정한 것**이다. 대시보드는 연도, 거래는 월, 분석은 토글, 연간결산은 다시 연도를 기준으로 삼는다. 그래서 연간 수치가 세 곳(대시보드·분석>연간·연간결산)에, 월간 수치가 세 곳(거래·분석>월·예산)에 나타난다. 화면을 옮기는 것만으로는 재발하므로 §5.7의 시간축 규칙이 필요하다.

### 4.2 상위 메뉴와 상세 화면의 위계가 뒤섞였다

`항목별 상세`는 분석 화면에서 카테고리를 선택한 후 도달해야 하는 상세 페이지지만 상위 메뉴에 노출된다. 반대로 핵심 목표인 예산은 `분석·예산` 드롭다운 안에 숨겨져 있다.

### 4.3 업무와 설정이 섞였다

파일 가져오기는 주간 핵심 업무지만 설정 메뉴에 중복 노출된다. 반대로 `미분류 거래`는 사용자가 처리해야 하는 작업 큐인데 기준정보 관리 화면에 들어가 있다.

### 4.4 화면이 기본 상태부터 너무 많은 정보를 보여준다

홈, 예산, 분석, 자산 화면이 요약과 세부 편집을 **접힘 없이 한 번에 전부 펼쳐** 보여준다. 사용자는 필요한 정보를 찾기 위해 긴 화면을 스크롤해야 하고, 모바일에서는 표와 폼이 계속 이어진다. 문제는 요약과 편집이 같은 화면에 있다는 것 자체가 아니라(예산처럼 보면서 고치는 화면은 함께 있어야 한다, §7.4) 우선순위 없이 모두 펼쳐진다는 점이다.

### 4.5 메뉴 용어가 가족 사용자에게 직관적이지 않다

- `인박스`는 내부 시스템 용어에 가깝다.
- `가계부`는 앱 전체와 거래 목록 화면을 동시에 뜻한다.
- `고정비용` 메뉴는 실제로 정기 수입·지출·저축을 모두 관리하므로 기능 범위를 제대로 표현하지 못한다.
- `항목`과 `카테고리`, `분류`가 혼용된다.

### 4.6 모바일 내비게이션의 계층이 사라진다

데스크톱의 드롭다운 항목까지 모바일 메뉴에서 평면 목록으로 표시된다. 자주 쓰는 기능과 설정 기능의 우선순위가 구분되지 않는다.

## 5. 설계 원칙

### 5.1 사용 빈도가 높은 업무를 상위에 둔다

상위 내비게이션에는 수시·주간·월간으로 반복하는 핵심 기능만 둔다. 기준정보 수정처럼 드물게 사용하는 기능은 설정으로 이동한다.

### 5.2 한 화면은 하나의 질문에 답한다

| 화면 | 답해야 하는 질문 |
|---|---|
| 홈 | 지금 우리 집 재정은 괜찮은가, 무엇을 해야 하나? |
| 거래 | 그 달에 무슨 일이 있었고 왜 그랬는가? (요약 → 카테고리 → 가맹점 → 행, 배율만 다른 한 질문) |
| 가져오기 | 새 거래를 어떻게 가계부에 반영할 것인가? |
| 예산 | 다음 달·이번 달 얼마를 쓸 것인가, 속도는 적절한가? |
| 연간 | 올해 목표를 향해 가고 있는가, 어느 달이 문제였는가? |
| 자산 | 순자산이 얼마고 어떻게 변했는가? |
| 설정 | 앱의 기준과 자동화 규칙을 어떻게 관리하는가? |

"분석"은 화면이 아니다. 한 달의 분석은 거래 화면의 요약·카테고리·가맹점 탭이고, 한 해의 분석은 연간 화면이다. 분석이라는 활동 이름 대신 시간축 이름으로 화면을 부른다.

### 5.3 요약과 상세를 분리한다

홈은 신호와 요약만 제공한다. 연 단위 상세표는 연간으로, 월 단위 상세와 원장은 거래로, 입력 폼은 해당 화면의 편집 모드로 이동한다 (예산은 예외, §7.4).

### 5.4 작업 큐와 기준정보를 분리한다

- 작업 큐: 검토 대기, 미분류 거래, 월말 리뷰, 이번 달 정기거래 반영
- 기준정보: 결제수단, 카테고리, 가맹점 규칙, 별칭, 정기거래 규칙

### 5.5 상세 화면은 문맥을 통해서만 진입한다

카테고리 상세, 월말 리뷰처럼 특정 상태가 필요한 화면은 상위 메뉴에 노출하지 않는다. 상위 화면에서 선택한 기간과 필터를 유지해 진입하고, 돌아갈 위치를 명확히 제공한다.

### 5.6 점진적으로 정보를 공개한다

긴 입력 폼과 상세표를 처음부터 모두 펼치지 않는다. 탭, 편집 모드, 드로어 또는 펼치기를 사용해 현재 작업에 필요한 정보만 보여준다.

단, 탭은 **보기와 편집처럼 모드가 실제로 다를 때만** 쓴다. 탭은 내용을 숨기고 URL 상태를 늘리므로 화면당 4개를 넘기지 않고, 내용이 겹치는 탭은 합친다.

### 5.7 시간축마다 정본 화면은 하나다

| 시간축 | 정본 화면 | 배율 |
|---|---|---|
| 이번 달 (현재 진행) | 홈 | 신호와 요약만 |
| 선택한 월 | 거래 | 요약 → 카테고리 → 가맹점 → 행 (탭) |
| 이번 달·다음 달 (계획) | 예산 | 카테고리별 계획 |
| 올해·선택한 해 | 연간 | 연 KPI → 항목별 월별 표 → 월 |
| 월말 스냅샷 | 자산 | 계정별 잔액 |

- **연도 선택기는 연간 화면에만** 있다. 홈은 이번 달에 고정하고 월 이동을 두지 않는다.
- 같은 달 안에서 배율만 바뀌는 것(합계 → 카테고리 → 가맹점 → 거래 행)은 **화면 이동이 아니라 탭 이동**이다. 그래야 필터가 한 번만 잡힌다. 이 규칙이 거래와 분석을 한 화면으로 합치는 근거다.
- 홈의 추이 차트는 **올해 1월부터 현재 월까지**(달력 연도 프레임)를 보이고 연 누적 수입·지출·순저축을 캡션으로 붙일 수 있다. 연도를 바꾸는 컨트롤과 연 누적 KPI 카드는 홈에 두지 않는다. 연간 화면의 예고편 역할이며, "다른 해는 연간에서"로 링크한다.
- 다른 화면이 같은 시간축의 같은 수치를 보여야 하면 그 정본 화면으로 링크한다.

## 6. 목표 메뉴 구조

### 6.1 데스크톱

```text
우리집 가계부
├─ 홈          이번 달 조종석 + 해야 할 일
├─ 거래        선택한 달 · 탭: 요약 | 카테고리 | 가맹점 | 목록
├─ 가져오기 [대기 건수]
├─ 예산        이번·다음 달 계획
├─ 연간        올해 조망 · 연도 선택기 · 항목별 월별 표
├─ 자산
└─ 설정 ⚙
   ├─ 결제수단
   ├─ 카테고리
   ├─ 가져오기 규칙
   ├─ 정기거래 규칙
   ├─ 자산 계정
   └─ 계정 및 보안
```

상위 메뉴 순서는 `현황 → 기록 → 입력 → 계획 → 연간 → 자산` 흐름을 따른다. 시간축으로 읽으면 이번 달(홈) → 선택한 달(거래) → 다음 달(예산) → 올해(연간)다.

거래 메뉴의 라벨은 "월간"이 시간축 이름으로 더 정합적이지만 낯설다. 사용자가 찾는 단어는 "거래"이므로 라벨은 거래로 두고, 그 안에 요약·카테고리·가맹점 탭을 둔다. 구조는 같다.

### 6.2 모바일

```text
홈 | 거래 | 가져오기 | 예산 | 더보기
```

`더보기`에는 연간, 자산, 설정을 그룹별로 표시한다. 가져오기에는 대기 건수 배지를 유지한다.

### 6.3 메뉴 용어

| 현재 | 변경 | 비고 |
|---|---|---|
| 대시보드 | 홈 | 첫 화면의 역할을 강조. 연 KPI·항목별 표는 연간으로 |
| 가계부 | 거래 | 선택한 달의 요약·카테고리·가맹점·목록을 한 화면에 |
| 분석 | 거래의 탭 (월간) · 연간 (연) | 독립 메뉴 제거. 활동 이름이 아니라 시간축 이름으로 |
| 항목별 상세 | 거래 › 카테고리 탭의 필터 상태 | 라우트 제거 |
| 연간결산 | 연간 | 독립 화면으로 유지·확장. 연도 선택기는 여기에만 |
| 인박스 | 가져오기 | 파일 업로드와 검토 흐름 전체를 표현 |
| 고정비용 | 정기거래 | 수입·지출·저축을 모두 포함 |
| 항목 | 카테고리 | 사용자 노출 용어를 하나로 통일 |

라우트 이름은 1차 개편에서 유지할 수 있다. 먼저 화면명과 내비게이션만 변경하고, URL 변경이 필요할 때 기존 주소에 리디렉션을 추가한다.

## 7. 화면별 기획

## 7.1 홈

### 목적

앱을 열었을 때 10초 이내에 현재 상태와 해야 할 일을 파악한다.

### 기본 기간

- **이번 달 고정.** 월 이동을 두지 않는다 (§5.7). 홈에 월 이동이 있으면 임의 월 조회 화면이 되어 거래·분석과 경계가 다시 흐려진다.
- 과거 월은 거래, 다른 해는 연간에서 본다.

### 목업

`docs/design/swiss-ledger/dashboard-v2.html`이 홈의 목업이자 정본이다. 아래 구성은 그 목업의 순서를 그대로 따르며, 데이터 매핑과 신규 쿼리는 `docs/handoff-dashboard-v2.md`에 있다.

### 화면 구성

1. 페이지 헤더
   - `홈`
   - 현재 기준 월과 진행도 (`20일 경과 / 31일`)
2. 히어로: 세 가지 질문 (지표 5개 이하)
   - 목표대로 가고 있나: 순저축률 진행 링 + 30% 목표 눈금
   - 더 써도 되나: 남은 돈(저축 목표 기반 지출 상한 기준) + 하루 사용 가능액. "썼다"가 아니라 "남았다"로 쓴다
   - 자산이 늘고 있나: 순자산 + 전월 대비 + 스파크라인
3. 해야 할 일 (최대 3줄, 우선순위: 이례적 지출 → 지출 속도 경고 → 검토 대기, 그 뒤 미분류·월말 리뷰·정기거래 미반영)
   - **집계 쿼리가 새로 필요하다.** 현재 `getDashboardData`는 검토 대기 건수와 페이스 경고만 준다. 미분류 건수(현재 `manage` 쿼리), 정기거래 미반영 여부(`recurring`), 월말 리뷰 필요 여부(다음 달 예산 부재)를 한 곳에서 모아 우선순위를 매기는 `getHomeTodos` 성격의 함수가 필요하며 `handoff-dashboard-v2.md`의 신규 쿼리 목록에 추가한다
4. 순자산 추이 12개월 + 이번 달 돈의 흐름(워터폴: 수입 → 고정비 → 변동비 → 저축 납입 → 잔여)
5. 예산 대비 지출 (불릿 차트, 상위 대분류)
6. 카테고리별 추세 (표 + 6개월 스파크라인 + 가장 큰 지출처) → 행 클릭 시 거래 › 카테고리 탭으로 필터 적용해 진입
7. 월별 수입·지출 + 월별 저축률 (목표 30% 점선). **올해 1월부터 현재 월까지** 달력 연도 프레임, 연 누적 수입·지출·순저축은 캡션으로. 연도 바꾸기는 없고 "다른 해는 연간에서"로 링크 (§5.7)

### 기존 거래 화면에서 이관되는 것

거래 화면 상단의 남은 돈(safe-to-spend), 월말 지출 예측, 월 KPI, 경고 배너는 전부 홈으로 옮긴다. 이 이관이 §4의 "거래가 사실상 월 대시보드" 문제를 해소하는 핵심 작업이다.

### 제거·이동

- 항목별 월별 표 (대분류›소분류 × 월, 셀 제외·호버) → **연간** (중심 컴포넌트)
- 결제수단 월별 표·카테고리 월별 라인차트 → **연간**
- 전체 가맹점 순위표 → **거래 › 가맹점 탭**
- 연도 선택기와 연 누적 KPI 카드 → **연간**
- 재무건강 4타일 → 자산 (천천히 변하는 지표라 매일 볼 홈에는 두지 않는다)

### 성능 효과

홈에서 연간 카테고리 상세 데이터를 제거하면 초기 DB 조회량과 렌더링할 표의 크기를 함께 줄일 수 있다.

## 7.2 거래

### 목적

선택한 달에 무슨 일이 있었는지 **합계에서 행까지 한 화면에서** 내려간다. 거래를 빠르게 찾고 입력하고 수정한다.

### 왜 분석과 한 화면인가

한 달의 요약(카테고리 순위, 가맹점, 전월 대비)과 그 달의 거래 행은 같은 데이터의 배율 차이다. 화면을 나누면 "식비가 왜 늘었나"를 좇는 동안 홈 → 카테고리 상세 페이지 → 거래 화면으로 세 번 이동하며 필터를 매번 다시 잡는다. 한 화면의 탭이면 필터는 한 번 잡히고, 카테고리 상세 페이지라는 라우트가 통째로 사라진다 (§5.7).

### 공통 헤더와 필터 (모든 탭이 공유)

- 월 선택 · 거래 건수 · 주요 액션(거래 추가, 이번 달 정기거래 반영)
- 필터 한 줄: 거래 유형(지출·수입·저축) · 카테고리(대분류) · 결제수단. 탭을 바꿔도 유지되고 URL에 실린다.
- 얇은 요약 바: **현재 필터 결과의 합계** (예: `식비 · 현대카드 · 14건 · 342,000원`). 필터가 없을 때만 월 전체 수입·지출·순저축. 홈 히어로를 반복하는 용도가 아니다.

### 탭

```text
요약 | 카테고리 | 가맹점 | 목록
```

- **요약**: 전월 대비 변화 · 그 달의 수입·지출·순저축과 저축률 · 평소보다 큰 지출(이상 탐지) · 큰 거래 TOP · 가장 많이 증가한 카테고리. 홈이 "이번 달"에 대해 하는 일을 임의의 달에 대해 한다.
- **카테고리**: 대분류 순위와 전월 대비 증감 막대. 대분류를 클릭하면 **페이지 이동 없이 카테고리 필터가 걸리고** 아래에 소분류 분해와 그 카테고리의 가맹점이 펼쳐진다. 여기서 "거래 보기"를 누르면 같은 필터로 목록 탭. 옛 `/category` 페이지의 내용이 전부 이 상태다.
- **가맹점**: 가맹점별 금액·건수·전월 대비, 검색. 가맹점 클릭 → 그 가맹점 필터로 목록 탭.
- **목록**: 거래 행. 가맹점·메모 검색, 미분류만 보기(목록 전용 필터). 행 클릭 편집, 인라인 저장·취소, 필요한 경우 일괄 분류.

### 기본 탭 규칙

- 메뉴에서 직접 진입: **목록** (거래를 찾으러 오는 경우가 가장 많다)
- 홈·연간의 링크로 진입: 링크가 가리키는 탭 (예: 홈의 "식비 ▲184,000" → 카테고리 탭 + 식비 필터)
- 탭과 필터는 URL 쿼리에 있어 새로고침·뒤로 가기·공유가 예측 가능하다.

### 로딩

탭마다 필요한 데이터만 불러온다. 네 탭을 한 번에 채우면 스펙이 없애려던 "긴 화면"이 다른 형태로 돌아온다. 공통 헤더의 월 합계는 가볍게 먼저, 탭 내용은 그 뒤에.

### 제거·이동

- 상단의 남은 돈·월말 예측·월 KPI·경고 배너 → 홈 (§7.1)
- 상세 예산 현황 → 예산
- 결제수단·카테고리 월별 표 → 연간

### 정기거래

- 거래 화면에는 `이번 달 반영 여부`와 실행 버튼만 제공한다.
- 규칙 생성·수정·비활성화는 설정의 `정기거래 규칙`에서 수행한다.

## 7.3 가져오기

### 목적

새 파일을 업로드하고, 추천 결과를 확인한 뒤 안전하게 거래로 반영한다.

### 화면 내 탭

```text
검토 대기 [N] | 파일 업로드 | 처리 기록 | 미분류 거래 [N]
```

### 기본 탭 규칙

- 검토 대기 거래가 있으면 `검토 대기`
- 검토 대기가 없으면 `파일 업로드`
- URL에 탭 상태를 유지해 새로고침과 뒤로 가기가 예측 가능해야 함

### 검토 대기

- 월별 그룹
- 월 안에서 결제수단 또는 원본 파일별 그룹
- 그룹 단위 펼치기·접기
- 고확신과 확인 필요 구분
- 중복 의심, 결제대행, 추천 출처 배지
- 그룹 선택 및 일괄 반영
- 선택 작업 바는 스크롤 중에도 접근 가능하게 유지

### 파일 업로드

- 뱅크샐러드와 카드 명세서 유형 선택
- 카드사와 소유자 선택
- 진행률과 처리 단계 표시
- 업로드 후 검토 대기 탭으로 이동
- 신규·중복·제외·확인 필요 건수를 결과 요약으로 표시

### 처리 기록

- 업로드 단위 또는 처리 일시 단위로 표시
- 반영·제외 건수 확인
- 필요하면 해당 월 거래로 이동

**데이터 소스 결정이 필요하다.** 현재 스키마에는 업로드 배치 테이블이 없다. `import_inbox`에는 행마다 `status`(pending/done/dismissed), `created_at`, `source`만 있다. 선택지는 둘이다.

1. **근사 그룹핑 (권장, 1차)**: `(source, created_at의 날짜)`로 행을 묶어 기록으로 보인다. 스키마 변경이 없어 §14 비범위와 충돌하지 않는다. 같은 날 같은 소스를 두 번 올리면 하나로 합쳐지는 한계는 화면에 명시한다.
2. **업로드 배치 테이블 추가 (2차)**: 파일명·업로드 시각·건수 요약을 저장한다. 정확하지만 스키마 변경이므로 별도 결정으로 미룬다.

### 미분류 거래

- 이미 가계부에 반영됐지만 카테고리가 없는 거래를 표시
- 현재 `/manage?tab=unclassified` 기능을 이동
- 분류 완료 후 거래 화면의 해당 월로 이동 가능

## 7.4 예산

### 목적

이번 달 예산의 상태를 확인하고, 필요한 경우 계획을 수정한다.

### 원칙: 예산은 지출 상한을 나누는 것이다

계획 도구가 둘이다. 저축 목표(목표율 → 지출 상한 = 월평균수입 × (1 − 목표율))와 카테고리 예산(대분류별 금액의 합). 지금은 둘이 독립 입력이라 서로 어긋날 수 있고, "남은 돈이 두 종류"는 그 증상이다.

**상한이 먼저고, 카테고리 예산은 상한의 분배다.** 화면은 이 관계를 강제한다.

- 상한은 화면 상단에 기준선으로 고정되어 있고, 카테고리 예산 합계가 그 아래 항상 함께 보인다 (`합계 5,600,000 / 상한 5,610,000 · 여유 10,000`).
- 합계가 상한을 넘으면 저장 전에 그 자리에서 초과액이 보인다. 저장을 막지는 않는다(비정기 지출이 큰 달은 넘길 수 있다). 대신 그 달의 예상 저축률을 옆에 보여 무엇을 감수하는지 알게 한다.
- 시뮬레이터는 이 원칙의 도구다: 변동비를 줄였을 때 합계가 상한 아래로 들어오는지, 저축률이 목표에 닿는지를 보인다.
- 월말 리뷰의 "상한 정합성 푸터"도 같은 규칙을 쓴다.

### 화면 구조

탭 대신 **한 화면에 현황과 편집을 함께** 둔다. 예산은 "보면서 고치는" 화면이라 보기와 편집이 분리된 모드가 아니다. 시뮬레이터만 기본 접힘으로 두고 필요할 때 펼친다.

```text
[기준선]     목표 저축률 · 지출 상한 · 카테고리 합계 vs 상한 (여유/초과)
[현황 요약]  사용 · 남음(상한 기준) · 진행률 대비 사용률 · 월말 예상 초과
[카테고리 행]  각 행 = 예산 입력칸 + 사용액 + 남은 금액 + 페이스 (불릿, 홈과 같은 표현)
               고정비 · 변동비 · 비정기 그룹으로 묶음
[도구]      이전 달 채우기 · 월평균으로 채우기
[펼치기]    절약 시뮬레이션
```

### 현황과 편집

- 카테고리 행 자체가 입력칸이다. 별도 편집 모드 진입 없이 숫자를 고치고 저장한다.
- 변경사항이 있을 때만 저장 액션을 강조한다.
- "남은 돈"은 홈과 같은 정의(저축 목표 기반 지출 상한)를 쓴다. 예산 합계 기준 잔액을 나란히 두지 않는다. 두 값이 비슷해 오타로 읽힌다.

### 절약 시뮬레이션 (펼치기)

- 변동비별 감축액 또는 감축률 조정
- 예상 순저축률 표시
- 목표까지 필요한 추가 감축액 표시
- 결과를 카테고리 행의 예산 입력칸에 반영

### 월말 리뷰

- 예산 화면의 하위 흐름으로 유지
- 월말 또는 다음 달 예산이 없을 때만 주요 액션으로 강조
- 지난달 실제와 예산 차이를 보고 다음 달 예산을 생성

## 7.5 연간

### 목적

올해(또는 선택한 해)를 조망한다. 30% 저축률은 연 단위로 판정되는 성적표이므로, 이 화면이 그 성적표다. 옛 대시보드의 연 KPI·항목별 월별 표와 연간결산(`/report`)이 여기로 모인다. 사실상 옛 Flask 대시보드의 후계자다.

### 연도 선택기

- 앱에서 연도를 바꾸는 컨트롤은 **이 화면에만** 있다 (§5.7).
- 진행 중인 해는 완료월 기준으로 월평균을 내고, 현재 월은 "진행" 표시와 함께 합계에는 넣되 평균 분모에서 뺀다 (기존 규칙 유지).

### 화면 구성

1. 연 KPI: 연 누적 수입 · 지출 · 순저축 · 순저축률(목표 30% 대비, 달성 개월 수). 전년 같은 기간 대비 증감.
2. 월별 저축률 (12개월, 목표 30% 점선, 달성·미달 월 표시, 최고·최저 월)
3. 월별 수입·지출 막대
4. **항목별 월별 표 (중심 컴포넌트)**: 대분류 › 소분류 × 월, 합계·월평균, 셀 클릭으로 합계 제외, 셀 호버로 그 (항목, 월)의 거래 내역. Flask 시절부터 가장 많이 쓴 도구이므로 이 화면의 본체다. 표현은 `docs/design/swiss-ledger/dashboard.html`의 항목별 월별 표를 따른다. 셀의 "거래 보기"는 거래 › 목록 탭으로 해당 월·카테고리 필터를 걸어 이동.
5. 결제수단별 월별 표 (항목별 표와 같은 자리, 전환 토글)
6. 연간 지출 TOP 카테고리·가맹점
7. 전년 대비 (수입·지출·순저축·저축납입)
8. 현금흐름 예측 (기존 `/report`의 6개월 예측)

### 제거·이동

- `/report`의 내용은 전부 이 화면에 흡수된다. 라우트는 재사용한다 (§11).
- 월 단위 분석(전월 대비, 이상지출, 가맹점 순위)은 거래 화면의 탭이다. 연간에는 두지 않는다.

### 카테고리 상세 페이지에 대해

없다. 한 카테고리의 소분류·가맹점·거래는 거래 화면의 카테고리 탭에 필터가 걸린 상태다 (§7.2). 연간의 항목별 표에서 카테고리를 클릭하면 그 상태로 진입한다. 옛 `/category` 주소는 리디렉션 (§11).

## 7.6 자산

### 목적

순자산 변화와 현재 자산 구성을 확인한다.

### 기본 화면

- 총자산
- 부채
- 순자산
- 현금성·투자자산
- 비상금 여력
- 부채비율
- 순자산 추이
- 자산 배분

### 잔고의 두 경로

잔액 스냅샷은 **뱅크샐러드 업로드 시 자동으로 기록된다** (업로드 폼의 "자산 스냅샷 반영" 체크, 기본 켜짐). 수동 입력은 주 경로가 아니라 **보정 수단**이다. 화면은 이 관계를 드러내야 한다.

- 기본 화면 상단에 `마지막 스냅샷: 8월 25일 · 뱅크샐러드 업로드`처럼 출처와 시점을 표기
- 자동 스냅샷에 없는 계정(부동산, 자녀 계좌 등)만 수동 입력 대상으로 안내
- §2.5 "월간 자산 업데이트" 업무는 실제로는 "업로드 후 빠진 계정만 채우기"로 가벼워진다

### 잔고 입력 (보정)

- `잔고 보정` 버튼으로 편집 모드 진입
- 모바일에서는 별도 화면, 데스크톱에서는 패널 또는 화면 내 모드 사용 가능
- 미입력 시 직전 잔액 유지 규칙을 입력 화면에서 명확히 설명

### 설정으로 이동할 기능

- 자산 계정 추가
- 자산 계정 이름 변경
- 자산 그룹 또는 정렬 관리

## 7.7 설정

### 목적

자주 바꾸지 않는 가계부 기준과 자동화 규칙을 관리한다.

### 구조

```text
설정
├─ 결제수단
├─ 카테고리
├─ 가져오기 규칙
│  ├─ 가맹점 사전
│  └─ 뱅크샐러드 결제수단 별칭
├─ 정기거래 규칙
├─ 자산 계정
└─ 계정 및 보안
   └─ 비밀번호 변경
```

데스크톱에서는 좌측 로컬 내비게이션, 모바일에서는 설정 목록 화면 후 상세 화면으로 이동하는 구조를 권장한다.

## 8. 공통 화면 구조

### 8.1 앱 헤더

- 로고 클릭 시 홈으로 이동
- 상위 메뉴 6개만 표시
- 설정은 우측 아이콘 또는 사용자 메뉴로 분리
- 이메일 전체를 항상 표시하지 않고 사용자 메뉴 안에 표시
- 활성 메뉴는 현재 상세 화면의 상위 섹션을 기준으로 표시

### 8.2 페이지 헤더

모든 주요 화면은 다음 순서를 따른다.

```text
섹션 설명
화면 제목                         기간 선택 / 주요 액션
짧은 설명
────────────────────────────────────────────────────
```

### 8.3 콘텐츠 폭

- 일반 요약 화면: 최대 폭 약 1,360~1,440px
- 거래·가져오기처럼 큰 표가 필요한 화면: 더 넓은 전용 레이아웃 허용
- 텍스트와 짧은 폼: 약 640~800px
- 모든 화면에 무조건 `max-w-none`을 사용하지 않음

### 8.4 상태 메시지

- 여러 색상 배너를 세로로 쌓지 않음
- `해야 할 일` 목록 또는 한 줄 상태로 통합
- 성공·오류는 작업 직후 짧게 표시
- 경고는 사용자가 할 수 있는 액션이 있을 때만 강조

### 8.5 로딩

- 전체 화면을 비우지 않고 기존 앱 셸과 페이지 헤더 유지
- 표와 차트 영역만 스켈레톤 또는 진행 상태 표시
- 페이지 이동 시 기존 내용이 갑자기 사라지는 전환을 최소화

## 10. 반응형 정책

### 10.1 모바일 우선순위

1. 해야 할 일 확인
2. 거래 검색·수정
3. 파일 업로드와 검토
4. 예산 잔액 확인
5. 상세 분석

### 10.2 모바일 표

- 요약 정보는 카드 또는 2열 행으로 전환
- 편집 열이 많은 표는 필수 열만 먼저 표시
- 행을 선택하면 상세 편집 패널을 열기
- 가로 스크롤이 필요한 경우 헤더와 첫 열을 고정
- 일괄 작업 바는 화면 하단에 고정할 수 있음

### 10.3 모바일 메뉴

- 하단 메뉴는 최대 5개
- 설정 항목을 메인 메뉴와 섞지 않음
- `더보기`에서도 업무와 설정을 별도 그룹으로 표시

## 11. 라우트 전략

### 11.1 1차: 기존 URL 유지

- `/dashboard` → 화면명만 `홈`
- `/ledger` → 화면명 `거래`, 탭 쿼리 `?tab=summary|categories|merchants|list` 추가 (기본 `list`)
- `/report` → 화면명 `연간`, 라우트 재사용
- `/inbox` → 화면명만 `가져오기`
- `/budgets`, `/assets` 유지
- `/manage`, `/recurring`, `/settings`는 설정 화면의 내부 링크로 유지

### 11.2 흡수되는 라우트 (리디렉션 필수)

- `/analysis?period=month&month=M&flow=F` → `/ledger?month=M&tab=summary&flow=F`
- `/analysis?period=year&year=Y` → `/report?year=Y`
- `/category?flow=F&major=X&month=M` → `/ledger?month=M&tab=categories&flow=F&major=X`
- `/category?...&period=year&year=Y` → `/report?year=Y` (항목별 표에서 해당 대분류 강조)
- `/manage?tab=unclassified` → `/inbox?tab=unclassified`
- `/recurring`은 규칙 관리 화면으로 유지하고 월 반영 액션만 거래로 이동

앱 안의 모든 내부 링크(홈·연간·가져오기에서 거래로 가는 링크 포함)는 새 주소를 직접 가리키게 갱신한다. 리디렉션은 북마크와 외부 링크용이다.

기존 북마크와 화면 간 링크가 깨지지 않도록 URL 변경은 항상 리디렉션과 함께 적용한다.

## 12. 구현 단계

### 1단계: 내비게이션과 용어

- 상위 메뉴를 홈, 거래, 가져오기, 예산, 연간, 자산으로 변경
- 설정을 우측으로 분리
- 항목별 상세, 분석을 상위 메뉴에서 제거 (연간결산은 `연간`으로 라벨만 바꿔 유지)
- 모바일 메뉴를 5개 구조로 변경 (더보기: 연간·자산·설정)
- 사용자 노출 용어 통일

### 2단계: 홈 = 이번 달 조종석, 거래 = 원장 (핵심 단계)

이 단계가 개편의 무게 중심이다. "거래가 사실상 월 대시보드"인 구조 왜곡(§3.2, §4)을 여기서 해소한다.

- 홈을 `dashboard-v2.html` 구성으로 구현 (`handoff-dashboard-v2.md`의 순자산 시계열·고정비/변동비 분해·할 일 집계 쿼리 포함)
- 거래 화면 상단의 남은 돈·월말 예측·월 KPI·경고 배너를 홈으로 이관
- 홈의 항목별 월별 표·결제수단 월별 표·연 KPI·연도 선택기를 **연간(`/report`)으로 이동**. 이 단계에서 연간은 "옛 대시보드의 연간 부분 + 옛 연간결산"을 한 페이지에 모은 상태면 충분하다. 다듬기는 5단계.
- 거래 화면의 요약 바를 필터 결과 합계로 재정의
- 정기거래 반영 상태를 거래에 추가

1단계 직후 이 단계까지만 끝나도 사용자가 체감하는 개편의 대부분이 달성된다. 여기서 한 번 실물을 보고 3단계 이후를 조정한다.

### 3단계: 가져오기 작업 공간 통합

- 검토 대기, 업로드, 처리 기록, 미분류 거래 탭 도입 (처리 기록은 1차 근사 그룹핑, §7.3)
- 업로드 후 검토 탭으로 자연스럽게 이동
- 월별·결제수단별 접기와 일괄 작업 개선

### 4단계: 예산 화면 정리

- 상단에 지출 상한 기준선과 카테고리 합계 대비 여유/초과 (§7.4 원칙)
- 카테고리 행을 입력칸으로 통합 (현황 + 편집 한 화면), 시뮬레이터는 펼치기
- "남은 돈" 정의를 홈과 통일 (저축 목표 기반 상한)
- 월말 리뷰 진입 조건과 안내 정리

### 5단계: 거래 탭 통합과 연간 다듬기

- 거래에 탭 4개 도입 (요약·카테고리·가맹점·목록), 공통 필터 바, 기본 탭 규칙, 탭별 지연 로딩
- `/analysis`의 월간 부분을 요약·카테고리·가맹점 탭으로 흡수, `/category`의 내용을 카테고리 탭의 필터 상태로 흡수
- `/analysis`, `/category` 리디렉션 (§11.2)
- 연간 화면 구성을 §7.5 순서로 정리 (2단계에서 모아둔 것을 배치·다듬기)
- 홈·연간·가져오기에서 거래로 가는 링크를 탭·필터 쿼리로 갱신

### 6단계: 설정 통합

- 관리·정기거래·보안 설정의 로컬 내비게이션 구성
- 미분류 거래를 가져오기로 이동
- 정기거래 실행과 규칙 편집 분리
- 자산 계정 설정 이동

### 7단계: 반응형·일관성 정리

- 콘텐츠 최대 폭 규칙 적용
- 모바일 하단 내비게이션 적용
- 큰 표의 모바일 상세 편집 방식 적용
- 남아 있는 이전 카드·폼 스타일을 현재 디자인 시스템으로 통일

## 13. 완료 조건

### 정보 구조

- 상위 메뉴는 데스크톱 6개, 모바일 5개 이하이다.
- 같은 목적지로 가는 중복 메뉴가 없다.
- `/category` 라우트가 없다 (리디렉션만 남는다). 월말 리뷰는 상위 메뉴에 노출되지 않는다.
- "분석"이라는 메뉴가 없다. 월간 분석은 거래의 탭, 연간 분석은 연간 화면이다.
- 설정 화면에 처리 대기 작업이 포함되지 않는다.

### 핵심 업무

- 새 파일 업로드 후 3개 화면 이내에서 거래 반영을 완료할 수 있다.
- 홈에서 저축률, 예산 상태, 가장 큰 지출 변화를 10초 이내에 확인할 수 있다.
- "이번 달 식비가 왜 늘었나"를 홈 → 거래(카테고리 탭) → 목록 탭까지 **화면 이동 1회, 필터 재설정 0회**로 좇을 수 있다.
- 거래 화면에서 검색·필터·수정이 첫 화면 흐름 안에 있다.
- 예산 값을 고치는 데 별도 편집 모드 진입이 필요 없고, 변경 사항이 있을 때만 저장이 강조되어 저장 전·후가 구분된다.

### 모바일

- 자주 쓰는 네 기능이 한 번의 탭으로 접근 가능하다.
- 모바일 메뉴에 설정과 상세 화면을 포함한 긴 평면 목록이 나타나지 않는다.
- 거래와 검토 작업에서 페이지 전체의 가로 스크롤이 발생하지 않는다.

### 성능·전환

- 홈은 전체 카테고리 상세표를 초기 조회하지 않는다.
- 페이지 이동 시 앱 헤더와 페이지 구조가 유지된다.
- 긴 화면의 데이터·편집 기능은 탭 또는 사용자 액션 이후에 불러온다.

### 시간축·중복

- 연도 선택기는 연간 화면에만 있다. 홈·거래·예산에 연 누적 KPI 카드가 없다 (홈 하단 추이 차트의 올해 캡션은 허용, §5.7).
- 한 화면에 시간축 토글(월간/연간)이 없다.
- "남은 돈"은 앱 전체에서 한 가지 정의(저축 목표 기반 지출 상한)만 쓴다.
- 예산 화면은 카테고리 합계와 지출 상한의 차이를 저장 전에 보인다.
- 거래 화면 상단에 남은 돈·월말 예측·월 KPI 블록이 없다.

### 빈 상태·첫 실행

- 거래가 0건인 새 가구가 홈을 열면 빈 차트 대신 "첫 파일을 올려 시작하세요" 안내와 가져오기 진입 버튼이 보인다.
- 자산 스냅샷이 없으면 순자산 블록은 "자산을 입력하거나 뱅크샐러드 파일을 올리면 추이가 보입니다"를 보인다.
- 예산이 없는 달은 예산 블록이 "이번 달 예산 만들기"로 바뀐다.
- 어떤 화면도 데이터가 없을 때 빈 표나 0으로 채워진 카드를 그리지 않는다.

## 14. 비목표

- 저축률, 예산 페이스, 자산 계산식 변경
- 거래 데이터 구조 또는 가져오기 지문 변경
- 카테고리 체계 자체의 재설계
- 자동 분류 알고리즘 변경
- 가족 구성원 또는 권한 모델 확대
- 새로운 외부 서비스 도입
- URL을 한 번에 전면 변경하는 작업

## 15. 최종 사용자 흐름

개편 후 앱의 핵심 순환은 다음과 같다.

```text
홈에서 상태와 할 일 확인
          ↓
가져오기에서 파일 업로드·검토
          ↓
거래에서 반영 결과 확인·수정, 요약·카테고리 탭에서 변화 원인 확인
          ↓
예산에서 소비 속도 관리, 상한 안에서 다음 달 예산 조정
          ↓
연간에서 올해 성적표 확인
```

자산은 가져오기에 딸려 자동으로 갱신되고 빠진 계정만 월 1회 보정하는 가벼운 흐름으로 두며, 설정은 핵심 업무 중 필요할 때만 진입하는 보조 영역으로 둔다.

## 16. 출시 후 검증 지표

개편의 핵심 가설은 "사용자가 홈 대신 거래를 먼저 여는 이유는 거래 상단이 월 대시보드이기 때문"이다. 이 가설은 출시 후 확인할 수 있다.

- 세션 첫 진입 화면에서 홈의 비율이 거래보다 높아진다.
- 가져오기 후 첫 거래 반영까지의 화면 전환 수가 3 이하로 유지된다.
- 홈에서 분석·거래로 이어지는 링크 클릭이 있다 (홈이 종착지가 아니라 출발점으로 쓰인다는 신호).

측정은 서버 로그의 경로 순서만으로 가능하며 별도 분석 도구를 넣지 않는다 (§14).
