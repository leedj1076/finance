# 인박스 거래명 편집과 가져오기 지연 대응

- 대상: `finance-web`
- 기준 커밋: `f25644c7da6ffea557d2677384acd603e8d19793`
- 작업 브랜치: `feat/import-experience`
- 상태: 2026-09-09 사용자 승인 설계

## 1. 인박스 거래명 편집

검토 대기의 자동 분류·확인 필요 행은 같은 표에서 거래명을 직접 편집한다. 초깃값은 `merchant || memo || ''`이며, 분류·결제수단과 마찬가지로 그룹을 접었다 펼치거나 다른 행을 처리하거나 서버 오류가 발생해도 로컬 초안이 유지된다. Enter는 폼 제출로 해석하지 않는다.

개별 반영과 선택 반영은 초깃값과 달라진 거래명만 선택적 값으로 보낸다. 선택 반영에서는 선택한 행의 값만 전송하므로 선택하지 않은 빈 초안이나 200자를 넘는 기존 제목이 다른 행의 반영·제외를 막지 않는다. 명시적으로 보낸 값은 서버에서 공백을 제거한 뒤 1~200자인 문자열인지 모든 쓰기 전에 검사한다. 값을 보내지 않은 기존 호출과 자동 분류 일괄 승인에는 기존 초깃값을 그대로 사용한다.

검증된 거래명은 원장 `transactions.memo`에만 저장한다. `transactions.raw_merchant`, `import_inbox.merchant`, `import_inbox.memo`, `import_uid`, 출처·금액·날짜·분류·중복 판정과 처리 기록은 원본 그대로 둔다. 가맹점 학습도 편집 제목이 아니라 원본 가맹점을 키와 표시값으로 사용한다. 가구 범위와 `pending` 상태 제한, 한 트랜잭션 안의 반영, 가져오기 UID 충돌 시 중복 삽입 방지는 유지한다.

원장에서 검색한 거래명을 다시 찾을 수 있도록 목록과 필터 합계는 동일한 조건으로 원본 `raw_merchant` 또는 표시 제목 `memo` 중 하나가 검색어와 일치하면 포함한다. 기존 월·가구·결제수단·흐름·대분류 조건, 대소문자 무시와 SQL 와일드카드 의미, 합계 계산식은 바꾸지 않는다.

## 2. 가져오기 지연 대응의 확정 범위

가져오기 지연 대응은 `f648e9402931e1d34629c7bcf536cac2b538b412`까지 구현됐다. 대기 스냅샷의 중복 메모 갱신은 같은 가구·`pending` 상태·행별 일대일 의미를 보존한 파라미터 배치이며 한 배치는 최대 500건이다.

새 AI 분류 호출은 선택 사항이며 전체 `await`에 30초 기한을 둔다. SDK 자체 재시도는 사용하지 않고, 기한 초과나 실패 시 행을 버리지 않고 확인 필요 상태로 보낸다. 이는 전체 파일 업로드의 30초 제한이 아니며 운영 환경의 실제 처리 시간 측정 결과도 아니다.

가져오기 화면은 한 요청의 실제 `validating`·`reading`·`matching`·`classifying`·`saving`·`finalizing` 이벤트만 표시한다. 임의의 전체 진행률이나 완료를 만들지 않고, 실제 결과 또는 오류를 사용자가 확인할 때까지 유지한다. 브라우저를 닫은 뒤의 백그라운드 지속·재개는 보장하지 않는다.

이번 거래명 작업은 업로드 서비스, 진행 이벤트, 파서, AI 분류, 스키마와 지연 정책을 변경하지 않는다.

## 3. 검증 기준

- 개별·선택 반영에서 편집 제목 저장과 원본 가맹점·UID·학습 키 보존
- 값 생략 시 가맹점/메모 fallback과 200자를 넘는 기존 제목 호환
- 빈 값·201자 이상·문자열이 아닌 명시 값의 쓰기 전 거부와 일괄 원자성
- 다른 가구·완료·제외 행 차단, 재시도 중복 방지, 제외 시 원본 불변
- 원본 가맹점과 편집 제목 각각의 목록 검색 및 필터 건수·금액 일치, 다른 가구 제외
- 두 신뢰도 행의 편집, 그룹 재개방·다른 행 처리·실패 뒤 초안/선택/펼침 유지, Enter 제출 방지
- 데스크톱과 390px에서 기존 페이지 폭을 넘기지 않는 표·입력 배치
