# 월 전체 마감과 확정 통계

상태: 집계 범위와 세부 정책 모두 사용자 승인 완료 (2026-09-09, “진행”).
후속: 통계의 표시·집계 정책(§1 일부, §4 통계 행, 빈 월과 부분 연도, 비교와 예측의 잠정 표시, §6 cell-tx scope, §7 초기 빈 통계)은 `2026-09-09-month-close-ux-design.md`가 대체한다 (2026-09-09).
기준 코드: `4cfcdb1` (2026-09-09). 이 문서 작성은 코드·운영 DB·배포를 변경하지 않는다.

## 1. 목표와 승인된 범위

사용자는 내역을 정리하는 중인 월이 확정된 것처럼 통계에 나오는 혼란을 없애고 싶어 한다. 거래별 체크가 아니라 **가구의 한 달 전체를 마감**한다.

- 내역에서 월 전체를 확인하고 마감한다. 현재 탭·검색어·결제수단·유형 필터는 마감 범위를 바꾸지 않는다.
- `/report`는 마감한 월만 집계한다. 미마감은 0원이 아니다.
- 홈·예산·내역은 실제로 기록된 전체 거래를 계속 읽되 미마감 수치를 잠정으로 표시한다.
- 수입·지출·저축 정의, 순저축률, 반올림, 페이스·예측 산식, 자산 잔액, 가져오기 지문·분류 방식은 바꾸지 않는다. 통계에 넣을 월의 자격만 바꾼다.
- 마감은 금융기관의 결제·송금이나 미래 거래 생성을 실행하지 않는다.

## 2. 선택한 방식과 대안

**월 상태 + 변경 감지**를 사용한다. 거래는 지금 원장에 그대로 두고, 마감 여부로 통계 집계 대상을 선택한다. 마감 후 실제 내역 변경은 자동으로 마감을 무효화한다.

대안인 수정 잠금 방식은 늦은 명세서 반영과 인라인 수정을 매번 막는다. 월별 거래 복사본을 고정하는 방식은 원장과 통계에 별도 버전이 생겨 정정·툴팁·분류 유지 비용이 크다. 이번에는 둘 다 도입하지 않는다.

## 3. 상태와 동작

상태는 `미마감`, `마감`, `재확인 필요`다. 처음에는 미마감이며, 사용자의 명시적 확인으로만 마감된다.

### 마감

내역의 조회 월 옆에 상태와 `[월 마감]`을 표시한다. `2026-08 전체 마감`처럼 실제 대상 월을 명시한다.

- 한국 시간 기준으로 **끝난 월만** 마감할 수 있다. 진행 중인 이번 달·미래 월은 마감하지 않는다.
- 확인 창에는 필터와 무관한 전체 거래 건수, 수입·지출·저축 납입 합계, 해당 월 인박스 대기 건수, 미분류 건수, 미반영 정기거래 건수를 보여준다.
- 대기·미분류·미반영 정기거래는 확인할 경고이지 강제 반영 대상이 아니다. 경고가 있으면 누락 가능성을 인지했다는 별도 확인을 받아 마감할 수 있다. 중복 의심으로 남긴 인박스까지 억지로 반영하게 하지 않는다.
- 거래 0건인 끝난 월도 `거래 없는 월로 마감`을 명시적으로 확인하면 마감할 수 있다. 이런 월은 미마감과 달리 실제 0원이다.
- 거래 목록의 표시 상한과 관계없이 **전체 월**을 집계한다.
- 확인 창을 연 뒤 다른 창·가족이 거래를 바꿨으면 마감하지 않고 최신 요약을 다시 확인하도록 한다.
- 중복 클릭·같은 상태의 재요청은 멱등하게 처리한다.

### 마감 후 변경

기존 인라인 수정·가져오기 사용성을 유지한다. 거래를 수정하기 전에 별도 잠금 해제는 필요 없다.

- 원장 거래 추가·삭제·실제 값 변경 시 해당 월을 자동으로 `재확인 필요`로 전환한다. 통계에서는 즉시 집계 자격을 잃으며, 다시 확인하고 마감하면 재포함된다.
- 날짜를 다른 월로 옮기면 원래 월과 새 월 모두 적용한다.
- 수동 입력, 가져오기 개별/일괄 반영, 자동 추천 일괄 반영, 정기거래 월 반영, 미분류 개별/일괄 분류를 모두 포함한다.
- 동일한 값을 저장하거나 중복 가져오기가 실제 INSERT 없이 끝난 경우에는 마감을 해제하지 않는다.
- 인박스에 쌓기·수정·선택 제외·처리 기록 복원만으로는 원장이 바뀌지 않으므로 마감을 해제하지 않는다. 마감한 월에 새 대기 항목이 생기면 내역에 별도 검토 안내를 표시한다. **그 항목을 원장에 반영할 때** 재확인 필요가 된다.
- 마감한 월에서 `[마감 해제]`도 제공한다. 원장을 바꾸지 않고 다시 검토할 수 있으며 통계에서 제외됨을 안내한다.
- 실제 원장 변경 후 기존 성공 토스트에 `8월 마감이 해제되었습니다. 다시 마감하면 통계에 반영됩니다.`를 덧붙인다. 화면 전체 로딩·스크롤 초기화는 만들지 않는다.
- 계좌·분류 이름 같은 공통 표시명, 예산·목표율, 정기 규칙 자체, 자산 스냅샷은 마감한 거래의 복사본으로 고정하지 않는다. 이러한 설정 변경만으로는 원장 월을 해제하지 않는다. 특정 거래의 분류/계좌 변경은 해제 대상이다.

### 통계의 빈 월과 부분 연도

- 12개월 열과 기존 차트 전환·항목 선택·셀 제외·호버 동작을 유지한다.
- 미마감/재확인 월은 상태 문구 또는 `—`로 표시하고 차트 데이터는 `null`로 전달한다. 0원 막대·0원 툴팁·선 연결로 보간하지 않는다. 중간에 미마감 월이 끼어도 동일하다.
- 마감된 0원 월은 0으로 표시한다. 표의 월 평균 분모는 명시적으로 마감한 월 수이며, 마감된 0원 월도 포함한다. 마감 0개월이면 평균·달성률·예측은 `—`다. 산술 함수의 0 나눗셈 방어를 실제 1개월 집계처럼 노출하지 않는다.
- 헤더에는 `마감 3개월 · 미마감 5개월 · 3, 5, 8월 기준`처럼 실제 집계 월을 표시한다. 진행 중인 월과 미래 월도 구별한다.
- 마감 월이 하나도 없으면 `마감한 월이 없습니다`와 내역으로 가는 링크를 보여준다. 실제 거래 없음과 구분한다. 거래 합계가 0이라는 이유만으로 마감 데이터를 빈 상태로 판단하지 않는다.
- 셀 제외는 기존과 같이 화면 내 분석 상태일 뿐 마감이나 원장을 바꾸지 않는다. 미마감 셀은 제외·호버 거래 조회 대상이 아니다.
- 표·그래프뿐 아니라 추이 미니 차트, 전월 대비 툴팁, 최저/최고 월, 목표 달성 개수에도 같은 마감 월 마스크를 적용한다. 미니 차트에서도 빠진 월을 0으로 만들거나 시간축을 압축하지 않는다.

### 비교와 예측

- 전월 대비는 **바로 전 달과 선택 월이 모두 마감**일 때만 계산한다. 건너뛴 마감 월과 비교하지 않는다.
- 전년 비교는 선택 연도의 마감 월과 정확히 같은 월 번호를 전년에서 사용한다. 예: 올해 1·3월 마감이면 전년도 1·3월만 비교한다.
- 비교할 전년 월 중 하나라도 미마감이면 전년 증감과 TOP의 전년 증감을 표시하지 않고 `전년 동일 월 미마감`으로 안내한다. 올해 전체 합계와 전년 일부 합계를 섞지 않는다.
- 전년의 대응 월이 모두 마감되어 있고 금액만 0인 경우, 금액 차이는 표시하고 퍼센트는 기존의 0분모 처리를 따른다.
- 6개월 현금흐름 예측은 기존 선택 연도의 완료월 평균 방식을 유지하되 입력 월을 마감 월로 제한한다. 기준 월 목록을 표시한다. 데이터가 없으면 추정치를 만들지 않는다.
- 예측 시작 잔액은 기존 자산 조회 기준을 유지하되, 거래 마감 기준과 별개인 잔액 기준 월을 함께 표시한다.

## 5. 데이터와 동시성

### 월 상태 테이블 하나

`ledger_months`를 추가한다.

- 기본 키: `(household_id, month)`.
- `month`: 유효한 `YYYY-MM`.
- `revision`: 해당 월 원장의 단조 증가 변경 번호.
- `closed_revision`: 마지막으로 확정한 변경 번호, 미확정은 null.
- `closed_at`, `closed_by`: 마지막 마감 시간과 사용자. 마감 후 원장 변경 시에도 마지막 확인 기록으로 유지한다.
- `updated_at`: 상태/원장 변경 시간.

`closed_revision = revision`이고 마감 기록이 있을 때만 통계 포함이다. 기록이 없으면 미마감, 이전 마감 기록은 있으나 현재 버전이 다르면 재확인 필요다. 사용자의 마감 해제는 `closed_revision`을 null로 만든다. 별도 이벤트 버스·거래 스냅샷 복제·범용 승인 엔진은 만들지 않는다.

### 변경 감지와 마감의 원자성

- 원장 INSERT/UPDATE/DELETE의 DB 트리거에서 실제 영향을 받은 가구·월의 revision을 같은 DB 트랜잭션 안에서 올린다. 메모·가맹점·날짜·유형·금액·고정비 여부·분류·계좌를 변경 대상으로 삼고 실제 값이 같은 UPDATE는 제외한다.
- UPDATE가 두 월을 건드리면 정렬된 키 순으로 상태를 갱신한다. bulk 작업의 잠금 경합과 롤백도 통합 테스트한다. 실패한 트랜잭션은 거래와 월 상태 모두 롤백되어야 한다.
- 이 장치는 서비스의 여러 쓰기 경로와 승인된 유지보수 SQL에서도 마감 무효화가 누락되지 않게 한다. household 삭제 cascade에서는 월 상태를 다시 만들지 않는다.
- 마감 요약을 읽을 때 원장·월 revision을 하나의 일관된 읽기 스냅샷에서 구한다. 사용자가 확인한 revision을 제출하고, 마감 저장은 해당 revision일 때만 성공시키는 조건부 쓰기다. 확인 이후 거래가 바뀌었다면 최신 요약 확인을 요구한다.
- 마감과 원장 변경이 경합하면 변경이 먼저 반영되어 마감이 실패하거나, 마감 뒤 변경으로 재확인 필요가 되어야 한다. 변경된 원장이 마감 상태로 남아서는 안 된다.
- 새 테이블은 기존 RLS 원칙을 따른다. 가구 구성원만 같은 가구의 상태를 읽고 마감할 수 있다. 서버의 모든 Drizzle 쿼리에도 householdId 조건을 유지한다. 로그인 사용자의 ID를 사용하며 폼의 가구 ID·사용자 ID는 신뢰하지 않는다.
- 기존 authenticated 기본 GRANT를 고려해 임의 revision/마감 상태 직접 쓰기는 허용하지 않는 권한과 정책을 명시한다. 트리거에 권한 상승이 필요하면 고정 search_path, 제한된 EXECUTE, 원본 행의 가구에만 쓰는 SQL로 제한한다.

## 6. 구현 경계

- `src/features/month-close/`: 월 상태·요약 조회, 마감/해제 액션, 입력 검증, 공통 집계 자격, 내역의 마감 UI.
- `src/db/schema/`와 새 Drizzle SQL: 월 상태 모델, 제약, RLS/권한, 변경 트리거. 기존 거래에 개인별 마감 값을 넣지 않는다.
- `src/features/analytics/`: `/report`의 읽기 모델을 한 경계로 묶어 마감 월 목록과 거래가 같은 DB 스냅샷에서 나오게 한다. 현재 `/report`가 따로 부르는 `getReportData`, `getDashboardData`, `getCategoryDetails`의 입력 일관성을 맞춘다. 홈의 실시간 로더를 전역적으로 마감 필터로 바꾸지 않는다.
- 기존 `buildAnnualReport`, 월별/계좌별/카테고리별 집계 함수는 가능한 한 순수 계산을 유지하고 명시적인 집계 월 정보를 받는다. 숨은 기본값으로 홈까지 제한하지 않는다.
- `stats-monthly.ts`의 `null → 0` 정규화와 마지막 활성 월 이전을 모두 숫자로 만드는 부분은 표시용 월 자격 마스크와 분리한다. 숫자 합산과 차트의 빈 구간을 혼동하지 않는다.
- `/api/cell-tx`: 통계 호출은 마감 전용 scope와 해당 월 revision을 전달한다. 서버에서 자격과 revision을 다시 확인한다. 해제되거나 자료가 바뀌었으면 숫자 대신 갱신 필요 응답을 반환한다. 기존 내역용 live scope의 조회는 유지한다. 서버 응답과 클라이언트 툴팁 캐시는 scope·revision을 구분한다.
- `revalidateFinance`에 월 마감 도메인/읽기 화면을 추가한다. 마감·해제·원장 변경 뒤 통계·내역·홈·예산 등 관련 읽기를 갱신하고 클라이언트 수정 폼/스크롤은 보존한다. 실시간 협업 전송은 추가하지 않으며 다른 탭은 다음 조회 시 최신 상태를 받는다.
- DB 마감 무효화는 핵심 안전장치, 액션의 추가 메시지는 사용자 안내 역할로 분리한다.

## 7. 기존 데이터와 배포

**승인된 초기 정책은 모든 기존 월을 미마감으로 두는 것**이다. 과거에 입력됐다는 이유로 사용자가 확인했다고 추정하지 않는다. 기존 거래 값·날짜·소스·멱등 키는 변경하지 않는다. 처음에는 통계가 비어 있을 수 있고, 내역에서 마감한 월부터 나타난다.

사용자가 특정 월까지 이미 확인했다고 명시하면 그 범위는 별도 승인된 초기 처리로 기록한다. 이번 설계의 기본 마이그레이션에는 자동 과거 마감을 넣지 않는다. 일괄 마감 UI는 이번 범위에 포함하지 않는다.

배포 순서:

1. 로컬 테스트 DB에서 새 테이블·트리거·RLS를 먼저 검증한다.
2. 운영 DB 백업 후 추가형 마이그레이션을 적용한다. 기존 코드의 거래 쓰기를 트리거가 안전하게 처리하는지 검증한다.
3. 새 코드 배포를 확인한다. 기존 월을 임의로 확정하지 않는다.
4. 사용자가 선택한 월의 마감·해제·조회로 운영 상태를 확인한다. 테스트 목적으로 실거래를 추가·수정하지 않는다.

롤백 시 원장과 마감 기록은 삭제하지 않는다. 이전 코드는 마감 필터가 없으므로 원복하면 미마감 월도 통계에 나온다는 점을 명확히 알린다. 원복은 별도 판단이지 자동 동작이 아니다.

## 8. 검증 기준

기존 계산 회귀는 유지하며 집계 자격 변경이 있는 화면 테스트만 명시적으로 마감 fixture를 준비한다. 테스트를 통과시키려고 미마감 데이터를 몰래 마감으로 취급하지 않는다.

- 단위: 상태 도출, 월 유효성/한국 시간 경계, 0원 마감과 미마감 차이, 비연속 마감 월 마스크, 평균 분모, 전월/전년 자격, 마감 없는 예측, URL/scope 입력 검증.
- DB 통합: 가구 격리·RLS·권한, 기존 데이터 보존, 저장/해제 멱등성, revision 조건부 마감, INSERT/DELETE/실제 UPDATE 및 no-op 구분, 월 이동 양쪽 무효화, 날짜 이동 후 정기거래 UID 보존, 롤백·동시 요청·cascade 안전성.
- 쓰기 경로 통합: 수동·인박스 단건/일괄/고신뢰·정기거래·미분류 단건/일괄이 모두 무효화, 재업로드 중복 skip과 인박스 제외·복원은 미무효화, 알림과 서버 캐시 갱신.
- 통계 통합: 모든 블록과 툴팁의 마감 자격 일치, 홈·예산은 미마감 거래 포함 유지, `1월 마감 / 2월 미마감 / 3월 마감`에서 2월을 0으로 집계하지 않음, 마감 0원 월, 전년 대응 월 부족, revision이 바뀐 툴팁 요청.
- E2E: 필터가 걸린 내역에서도 전체 월 요약 확인 → 마감 → 통계 반영 → 인라인 수정 → 재확인 안내/통계 제외 → 재마감. 중간 미마감 월 그래프, 3개 차트 모드, 셀 제외·호버·미니 추이, 현재 월 마감 제한, 경고 동의, 키보드/모바일/다크모드, 깜빡임·스크롤 보존.
- 최종 검사: `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm test:all`, `pnpm build`, `pnpm e2e`.
