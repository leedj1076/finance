# 개발 요청 — 대시보드 개편 (데이터 가독성)

## 요청

대시보드를 `docs/design/swiss-ledger/dashboard-v2.html` 구성으로 재편한다.
UI 스킨 교체가 아니라 **무엇을 보여줄지 자체를 바꾸는 작업**이다. 새 쿼리가 필요하다.

시각 언어는 Swiss Ledger를 그대로 따른다 (`docs/handoff-ui-redesign.md`, `foundation.html`).

## 읽을 것

1. `docs/design/swiss-ledger/chart-specs.html` — **왜 이렇게 바꾸는지 + 구현 스펙**. 차트 타입 결정표, 새 컴포넌트 치수, 검증된 팔레트가 여기 있다. 먼저 읽을 것.
2. `docs/design/swiss-ledger/dashboard-v2.html` — 목업. 마크업과 SVG가 곧 명세다.
3. 라이브 캔버스: https://claude.ai/code/artifact/19387efa-0f62-42cd-8ff8-38162eb7a043 ("대시보드 개편" 페이지)

목업의 숫자는 전부 샘플이다.

## 왜 바꾸는가

지금 대시보드는 **스크롤 전에 지표 타일이 11개**다(KPI 4 + 재무건강 4 + 월 카드 3). 상단 지표가 5~9개를 넘으면 사용자가 읽기를 포기한다. 그리고 이미 계산되는 값 중 화면에 없는 것들이 있다.

첫 화면을 세 질문으로 줄인다: **목표대로 가고 있나 / 이번 달 더 써도 되나 / 자산이 늘고 있나.**

## 화면 구성 (위에서부터)

| 순서 | 블록 | 상태 |
|---|---|---|
| 1 | **히어로 3분할** — 저축률 진행 링(목표 눈금) · 남은 돈(손실 프레이밍) · 순자산+스파크라인 | 링/스파크라인 신규 |
| 2 | **알림 최대 3줄** — 이례치 → 페이스 초과 → 인박스 순. 7px 사각 점 + 한 줄 | 이상지출 노출 신규 |
| 3 | **순자산 추이 12개월** — 순자산 라인 + 총자산 점선 + 부채 영역 | **쿼리 신규** |
| 4 | **이번 달 돈의 흐름 (워터폴)** — 수입 → 고정비 → 변동비 → 저축납입 → 계좌 잔여 | **집계 신규** |
| 5 | **예산 대비 지출 (불릿)** — 막대=실제, 세로선=예산, 옅은 구간=적정 페이스 | 데이터 있음 |
| 6 | **카테고리별 추세 (표+스파크라인)** — 6개월 미니 라인 + 6개월 평균 + 전월 대비 + 최대 지출처 | 데이터 있음 |
| 7 | **월별 수입·지출 + 월별 저축률** — 저축률 차트에 목표 30% 점선 | 일부 있음 |

## 데이터 매핑

### 이미 `getDashboardData`가 반환 — 화면에만 붙이면 되는 것

- `current.savingsRate`, `savingsTarget` → 히어로 진행 링
- `budget.categories[]` (전체 대분류, `{major, budget, amount, remaining}`) → 불릿 차트. **지금은 상위 6개 `categoryRanks`만 쓰고 이 배열을 안 쓴다.**
- `budget.paceWarnings[]` → 알림 2번째 줄
- `categoryMonthly.expense.series` → 카테고리 스파크라인(최근 6개월 슬라이스)
- `categoryRanks[]` (`previous`, `delta`, `changeRate` 포함) → 추세 표의 전월 대비
- `merchantRanks[]` → 추세 표의 "가장 큰 지출처" 열
- `monthly[]` → 월별 수입·지출 막대, 월별 저축률 라인

### 이미 계산되는데 화면에 안 나오는 것

- `anomalyAlerts()` (`src/features/analytics/calculations.ts`) — Modified Z-score 이상 지출. 지금은 `insights` 8줄 안에 섞여 묻힌다. → **알림 1번째 줄로 승격**, 문장에 평소 수준과 비교를 넣을 것("평소 월 3만원대").
- `largestExpense` — 추세 표나 알림에서 활용.

### 새로 만들어야 하는 것

**(1) 순자산 시계열** — `src/features/analytics/net-worth.ts` (신규)

```
getNetWorthSeries(householdId, months = 12)
  → Array<{ month: 'YYYY-MM', assets: number, liabilities: number, netWorth: number }>
```
- 출처: `balanceSnapshots`(월별로 이미 쌓여 있음) + `assetAccounts.kind`(`'asset'` | `'liability'`)
- 계정별 최신 스냅샷을 월별로 이월(carry-forward)해야 한다. 어떤 달에 스냅샷이 없는 계정은 직전 달 잔액을 그대로 쓴다 — `src/features/assets/calculations.ts`의 `lastBalance` 로직과 같은 규칙.
- 스냅샷이 하나도 없으면 빈 배열을 반환하고, 화면은 "자산을 입력하면 추이가 보입니다" 빈 상태를 그린다.
- **householdId 필터 필수.**

**(2) 고정비/변동비 분해** — `getDashboardData` 확장

```
current.fixedExpense / current.variableExpense
```
- 출처: `transactions.fixed` boolean. 해당 월 지출을 `fixed` 기준으로 두 합계로 나눈다.
- 워터폴 5칸: `income` → `−fixedExpense` → `−variableExpense` → `−saving` → 잔여.
- 잔여 = `income − expense − saving`. 목업 캡션대로 **순저축 = 저축 납입 + 계좌 잔여**임을 한 줄로 밝힐 것.

**(3) 적정 페이스 기준선** — 불릿 차트의 옅은 구간
- `경과일 / 그 달의 총일수`. 과거 달을 보고 있으면 100%.

**(4) 할 일 집계** — `src/features/analytics/home-todos.ts` (신규)

```
getHomeTodos(householdId)
  → Array<{ kind, priority, title, detail, href }>  // priority 오름차순, 화면은 상위 3개만
```
- 소스가 흩어져 있어 한 곳에 모아야 한다: 이례적 지출(`anomalyAlerts`) · 지출 속도 경고(`budget.paceWarnings`) · 검토 대기 건수(`import_inbox` pending) · 미분류 거래 건수(현재 `manage` 쿼리의 unclassified) · 월말 리뷰 필요 여부(다음 달 예산 부재 + 월 후반) · 정기거래 미반영 여부(`recurring` 활성 규칙 중 이번 달 미생성).
- 우선순위는 이 순서로 고정: 이례적 지출 → 페이스 경고 → 검토 대기 → 미분류 → 월말 리뷰 → 정기거래.
- 각 항목은 그 작업을 처리하는 화면으로 바로 가는 `href`를 가진다 (검토 대기 → 가져오기, 미분류 → 가져오기의 미분류 탭, 월말 리뷰 → `/budgets/review`).
- **householdId 필터 필수.** 정보구조 기획서 §7.1 3번 항목이 이 함수를 전제한다.

## 컴포넌트 (`src/features/analytics/`에 신규)

`chart-specs.html`에 치수가 있다. 요약:

- **진행 링** — SVG. r=54, stroke-width 14, 트랙 `#f4f4f5`, 12시 시작 시계방향. 목표 눈금은 2px ink 짧은 선. 달성 green, 미달 ink(빨강 아님 — 진행 중인 달을 실패로 칠하지 않는다).
- **스파크라인** — SVG 110×26, 선 2px, 축·격자·라벨 없음, 마지막 점만 r=3. 색은 추세 판정(증가 red / 보합 muted / 감소 green). **수입·저축 행은 좋고 나쁨이 반대이므로 색 규칙을 뒤집을 것.**
- **불릿 차트** — div. 막대 12px, 예산선 2px ink(막대보다 위아래로 3px 김), 페이스 구간 `#f4f4f5`, 트랙 `#fafafa`. 초과일 때만 막대 red, 100% 넘으면 막대를 100%에서 자르고 수치로 초과율을 쓴다.
- **워터폴** — SVG. 각 칸은 이전 누적에서 시작, 점선으로 연결. 감소는 ink 계열, 최종 잔여만 green.

## 규칙

- **파이·도넛 차트 금지.** 구성비는 가로 막대나 표로.
- **이중 y축 금지.** 척도가 다른 두 계열은 차트를 나눈다.
- **모든 수치에 기준점을 붙인다** — 예산 대비 %, 전월 대비, 6개월 평균, 목표선 중 최소 하나. 맨숫자 금지.
- 시간 단위를 섞지 않는다. 대시보드는 월 기준이고, 제목 근처에 "20일 경과 / 31일"처럼 진행도를 명시한다.
- 카테고리 시리즈 색은 **고정 순서, 순환 금지**. 7번째부터는 "그 외"로 묶는다. 색은 항목에 붙어 필터로 개수가 바뀌어도 유지된다.
- 수입 blue / 지출 ink / 저축 green / 초과 red / 주의 amber는 **역할 고정색**이라 시리즈 색으로 재사용하지 않는다.
- 상태는 색만으로 전달하지 않는다 — 항상 라벨을 함께.

## 주의: "남은 돈"이 두 종류다

화면에 잔액이 두 개 있으면 안 된다.
- **저축 목표 기반 지출 상한** = 월평균수입 × (1 − 목표저축률). 예: 5,610,000
- **대분류 예산 합계** = `budget.total`. 예: 5,600,000

둘은 다른 개념인데 값이 비슷해 나란히 두면 오타로 읽힌다. **히어로의 "더 쓸 수 있는 돈"은 저축 목표 기반 상한 하나만** 쓰고(저축률이 최우선 목표이므로), 예산 섹션에서는 잔액 대신 사용률 %만 보여준다. 목업이 그렇게 되어 있다.

## 걷어낼 것

- KPI 4장 + 월 카드 3장 → 히어로 3칸. 연 누적 수입·지출은 월별 차트 옆 캡션으로 내린다.
- 재무건강 4타일 상시 노출 → 자산 섹션 안으로. 단, `status`가 `warn`이면 상단 알림으로 올린다.
- `insights` 8줄 → 최대 3줄(이례치 → 페이스 → 인박스). 나머지는 접는다.

## 함께 고칠 것 — 부채비율 지표

현재 `financial-health.ts`의 "부채비율"은 `부채 ÷ 총자산`이다. 표준 지표인 DTI는 `상환액 ÷ 소득`(36% 이하 권장)으로 **다른 것을 잰다.** 지금 값은 자산 건전성은 보여주지만 대출 감당 능력은 못 본다.

- 당장은 라벨을 "부채/자산 비율"로 명확히 하고 힌트에 그 뜻을 적는다.
- 대출 상환액을 식별할 수 있게 되면(고정비 카테고리나 `recurring`에서) DTI를 별도 지표로 추가한다. 이번 범위에서 강제하지는 않는다.

참고로 나머지 임계값은 통용 기준과 맞는다: 비상금 3~6개월 ✓, 고정비 50% ✓. 저축률 30%는 일반 권장(15~20%)보다 공격적인 사용자 목표이므로 유지하되, 힌트에 "일반 권장 15~20%"를 병기하면 30%가 얼마나 높은 목표인지 읽힌다.

## 검증

- `pnpm lint` · `pnpm exec tsc --noEmit` · `pnpm test` · `pnpm build` 전부 통과.
- 새 데이터 함수(`getNetWorthSeries`, 고정비/변동비 분해)는 **테스트를 새로 쓴다** — 캐리포워드, 스냅샷 없는 달, 자산 미입력, 부채만 있는 경우.
- 넓은 표는 `overflow-x-auto` 안에. 페이지 본문은 가로 스크롤이 생기면 안 된다.
- 모든 Drizzle 쿼리에 householdId 필터.

## 진행 방식

블록 단위 커밋. 순서: ① 순자산 쿼리+테스트 → ② 히어로 3분할(링·남은 돈·순자산) → ③ 알림 3줄(이상지출 승격) → ④ 순자산 차트 → ⑤ 고정비/변동비 분해 + 워터폴 → ⑥ 불릿 차트 → ⑦ 스파크라인 표 → ⑧ 하단 차트 정리 및 걷어내기.

①~②만 끝나도 첫 화면 목적은 달성되니, 거기서 한 번 실물을 보고 판단할 것.
